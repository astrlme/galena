---
title: Local development
description: Run the dashboard, API, background jobs, status page and a simulated hot path on your machine.
---

Everything runs locally with one command, with no account anywhere. You need Node 24, pnpm 11
(Corepack picks the version in `package.json`) and Docker.

<Steps>
<Step>

### Install and start

```bash
git clone https://github.com/astrlme/galena.git
cd galena
pnpm install
pnpm dev
```

`pnpm dev` starts Postgres 16 and DynamoDB Local in Docker, applies the migrations, seeds a
workspace, then runs every app:

| Port | What |
| --- | --- |
| 3000 | The dashboard (Next.js) |
| 4321 | The status page (Astro), built from a fixture snapshot |
| 8787 | The API (Hono on Node) |

The API shares one process with the background jobs and the hot path. Each minute, three
simulated probe regions check every enabled monitor, the evaluator writes results and state to
DynamoDB Local, where the dashboard reads them, and a state change starts the same jobs a
deployment runs: incidents, drafts and their deadlines, publishing, emails, Slack and webhooks.

</Step>
<Step>

### Sign in

Open [localhost:3000](http://localhost:3000/sign-in/) and sign in as `owner@example.com` with the
password `galena-local-owner`. The seed refuses any database but the local one, so this account
never exists anywhere else.

</Step>
<Step>

### Background jobs

The jobs run in that process, one at a time per lane as in a deployment, and write to disk
instead of AWS:

| What | Where |
| --- | --- |
| Published page files | `apps/workers/.local/pages/` |
| `monitors.json` | `apps/workers/.local/config/` |
| Emails | `apps/workers/.local/mail/`, one `.txt` and one `.html` per email |

The status page's dev server reads its fixture snapshot, so the page's HTML is built only with
`GLN_LOCAL_HTML=1`. A draft's deadline is real time: an unanswered draft settles ten minutes
after it opens. When the process restarts (it reloads on every saved file), it sends what the
outbox still holds and arms again every open draft's deadline and every unfinished maintenance
window.

</Step>
</Steps>

## Watching a local service

The SSRF guard refuses private and loopback addresses everywhere. To point a monitor at a
server on your own machine during development, start `pnpm dev` with `GLN_ALLOW_LOOPBACK=1`.
Every stage other than `local` ignores the switch.

## Checks

| Command | What it runs |
| --- | --- |
| `pnpm check` | Biome, oxlint, TypeScript, unit tests and the dependency rules |
| `pnpm test:int` | Integration tests against Postgres and DynamoDB Local in Testcontainers |
| `pnpm test:e2e` | Playwright with axe against local dev, in light and dark; stop `pnpm dev` first, it starts its own |
| `pnpm check:page` | The status page's JavaScript and HTML budgets, Lighthouse and axe |
| `pnpm replay` | The detection rules against recorded check results |
| `pnpm infra:synth` | CDK synth with cdk-nag |
