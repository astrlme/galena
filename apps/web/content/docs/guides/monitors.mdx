---
title: Add a monitor
description: Watch an endpoint from three regions and let it drive a component's status.
---

<Steps>
<Step>

### Pick the URL

Choose an address that fails when your users would notice. A health endpoint that checks its own
dependencies is ideal; a static file served by a CDN usually says nothing about your service.

The URL must be public: the probes refuse private and loopback addresses. During local
development, see [watching a local service](/docs/getting-started/local-development/#watching-a-local-service).

</Step>
<Step>

### Add it

In **Monitors**, choose **Add monitor** and fill in:

- **Monitor name**: what your team calls it, such as "API health".
- **URL**: `https://api.example.com/health`.
- **Method**: `GET`, or `HEAD` for endpoints that are slow to send a body. A `HEAD` check can't
  look for a keyword.
- **Keyword** (optional): the check fails when the response doesn't contain this text. Use it
  when an error page can still answer 200.
- **Component**: the component this monitor speaks for. Leave it empty to watch without changing
  the page.
- **When it goes down**: Major outage, or Partial outage for a monitor that covers only part of
  the component.
- **Publish policy**: see [Monitors and checks](/docs/concepts/monitors/#publish-policy).

</Step>
<Step>

### Watch the first results

Within a minute or two, the monitor's row shows the latest check from each region (hover a
region's mark for its answer time) and when it was last checked. Its state starts as **No data**
and settles once enough regions agree. The 24-hour median line, the 24-hour p95 and the 30-day
uptime fill in from the hourly rollup, at five past each hour.

</Step>
</Steps>

## Finding a monitor

**Down**, **Degraded performance** and **Paused** above the list show only the monitors in that
state, each with its count; **All** shows them all again. **Search** matches names and URLs (a
name's URL shows when you hover it), and every column with a number sorts when you press its
heading. On a narrow screen the list keeps the state and name, and the other columns appear as
there is room.

## A monitor's page

A monitor's name, in the list or in search (Ctrl K), opens its page:

- **Response times** for the last 24 hours, 7, 30 or 90 days: one chart per region on a shared
  scale, the median as a solid line and the p95 dashed, with incidents the monitor opened hatched
  behind them. Hover a chart for that hour's or day's numbers and where its time went (DNS,
  connect, TLS, first byte). Under each chart a sentence gives the range in numbers, and **Show as
  table** lists every point. The median and p95 above the charts count every region's answers
  together.
- **Uptime**: the last 90 days, one mark per day, as the status page draws them. Use the arrow
  keys on it to hear each day.
- **Last hour**: one mark per minute, and every check that failed in it with the probe's reason.

Charts come from hourly and daily rollups, so the newest hour appears at five past the next.

## Pausing

**Pause** stops the checks without deleting the monitor or its history. While paused, the
monitor has no say in its component's status. **Resume** starts the checks again. To pause or
resume several at once, tick their rows and press **Pause** or **Resume** above the list; through
the API, send their ids to `PATCH /v1/monitors`:

```bash
curl -X PATCH "$URL/v1/monitors" -b cookies.txt \
  -H 'content-type: application/json' -d '{"ids": ["<id>", "<id>"], "enabled": false}'
```

## Tuning

The dashboard sets the common fields. Accepted status codes, the timeout, redirects and
[detection settings](/docs/concepts/detection/#settings) are set through the API. `PUT` replaces
every field, so send the whole monitor:

```bash
curl -X PUT "$URL/v1/monitors/$ID" -b cookies.txt \
  -H 'content-type: application/json' -d '{
  "name": "API health",
  "componentId": "0199…",
  "http": {
    "url": "https://api.example.com/health",
    "method": "GET",
    "expectedStatus": [200, 204],
    "timeoutMs": 5000,
    "followRedirects": false
  },
  "publishPolicy": "approve",
  "downStatus": "major_outage",
  "detection": { "degradedLatencyMs": 1500, "stableMinutes": 10 },
  "enabled": true
}'
```

Detection fields you leave out take their defaults. See the [API reference](/docs/reference/api/)
for signing in from a script.
