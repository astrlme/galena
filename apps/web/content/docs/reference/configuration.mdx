## Deployment config

A deployment is described by `galena.config.json`, which is never committed; `pnpm galena init`
writes one. CDK reads it from
the repository root, or from the path in `-c config=<path>`, and validates it with Zod when it
synthesises. `infra/test/fixture.config.json` is a complete example with every option set.

| Field | Type | Meaning |
| --- | --- | --- |
| `stage` | lower-case name, up to 20 characters | Names every stack (`galena-<stage>-…`) and parameter (`/galena/<stage>/…`) |
| `homeRegion` | region | The API, database, queue, detection and the workers' AWS access |
| `probeRegions` | at least 3 regions | Where checks run |
| `pageRegions.primary`, `.replica` | regions | The status page's buckets; all three of these and `homeRegion` must differ |
| `pageDomain` | hostname, optional | The page's own domain; adds a certificate stack in us-east-1 |
| `webDomain` | hostname, optional | The dashboard's own domain; adds a certificate stack in us-east-1 and becomes the public URL |
| `siteDomain` | hostname, optional | The project's own site: the landing page and docs, without the dashboard. Only the maintainer's deployment sets it; leave it out |
| `email.domain`, `email.from` | optional | The SES identity, and the sender, which must be an address at that domain |
| `github` | optional | Deploying from GitHub Actions: adds the OIDC deploy role. Without it, deploy from your machine with your own credentials |
| `github.repository` | `owner/name` | Your repository. In Actions, synth refuses a config made for another repository |
| `github.oidcSubject` | `repo:owner@id/name@id` | The `sub` prefix of GitHub's OIDC tokens for your repository |
| `github.deployRef` | `refs/…` | The only ref whose workflows may assume the deploy role |
| `telemetryCapacity.read`, `.write` | integers | DynamoDB units; deployments in one account and region share the free tier of 25 each |
| `auroraMaxAcu` | 1 to 16 | Aurora's capacity ceiling; the floor is 0, so it pauses |
| `smoke` | boolean, default `false` | Adds the deployed smoke test's target and role; needs `github` |
| `retainData` | boolean, default `true` | Keeps the telemetry table and the config bucket if their stack is deleted |
| `triggerProjectRef` | `proj_…`, optional | The trigger.dev project the workers deploy to; the stacks don't use it, and `galena doctor` checks its production variables |

Every deployment keeps 14 days of database backups, turns on deletion protection for the
database and keeps it if its stack is ever deleted, whatever `retainData` says.

## SSM parameters

See [Data stores](/docs/architecture/data/#ssm-parameters). The four you create by hand are
`/galena/<stage>/auth-secret`, `/galena/<stage>/app-key`, `/galena/<stage>/trigger-secret-key`
and `/galena/<stage>/setup-token`.

## API

In AWS, CDK sets these on the Lambda. Locally, `pnpm dev` uses the defaults.

| Variable | Default | Meaning |
| --- | --- | --- |
| `GLN_STAGE` | `local` | `local`, `dev` or `prod` |
| `GLN_API_PORT` | `8787` | The local server's port |
| `GLN_PUBLIC_URL` | `http://localhost:3000` | The dashboard's address, where the API also answers |
| `GLN_PUBLIC_URL_PARAM` | | In AWS: the SSM parameter holding it |
| `GLN_DATABASE_URL` | the Docker database | Local Postgres |
| `GLN_DB_CLUSTER_ARN`, `GLN_DB_SECRET_ARN`, `GLN_DB_NAME` | | In AWS: the Data API |
| `GLN_AUTH_SECRET` / `GLN_AUTH_SECRET_PARAM` | | The session secret, or its SSM parameter |
| `GLN_APP_KEY` / `GLN_APP_KEY_PARAM` | a fixed local key | The app key, or its SSM parameter |
| `TRIGGER_SECRET_KEY` / `GLN_TRIGGER_SECRET_PARAM` | | trigger.dev's secret key, or its SSM parameter |
| `GLN_ORIGIN_SECRET_PARAM` | | In AWS: the secret header CloudFront adds |
| `GLN_TELEMETRY_TABLE` | `telemetry` | The DynamoDB table |
| `GLN_DYNAMODB_ENDPOINT` | | Locally, DynamoDB Local |
| `GLN_PROBE_REGIONS` | | The probe regions, comma-separated |
| `GLN_ALLOW_LOOPBACK` | `false` | Lets monitors reach loopback addresses; only honoured when the stage is `local` |
| `GLN_GITHUB_CLIENT_ID`, `GLN_GITHUB_CLIENT_SECRET` | | GitHub sign-in on the API, off when unset. The sign-in page has no GitHub button yet, and the stacks don't set these |

## Dashboard build

| Variable | Default | Meaning |
| --- | --- | --- |
| `GLN_SITE` | | `project` builds the project's own site (the landing page and docs) into `out-site/` for the `siteDomain` stack; otherwise `/` opens the dashboard. The Deploy workflow builds it when the repository variable of the same name is `project`; leave it unset. |

| Variable | Default | Meaning |
| --- | --- | --- |

| `GLN_CONFIG_BUCKET`, `GLN_CONFIG_KEY` | key `monitors.json` | The monitors file |
| `GLN_QUEUE_URL` | | The check results queue |

## Workers

Set in the trigger.dev project's environment; see
[Self-hosting](/docs/getting-started/self-hosting/#deploy-the-workers). Locally, from
`apps/workers/.env`.

| Variable | Default | Meaning |
| --- | --- | --- |
| `GLN_TRIGGER_PROJECT_REF` | | The trigger.dev project (`proj_…`) |
| `GLN_DATABASE_URL` | the Docker database | Local Postgres |
| `GLN_DB_CLUSTER_ARN`, `GLN_DB_SECRET_ARN`, `GLN_DB_NAME` | name `galena` | In AWS: the Data API; both ARNs or neither |
| `GLN_HOME_REGION` | `eu-central-1` | The Data API's and config bucket's region |
| `GLN_CONFIG_BUCKET`, `GLN_CONFIG_KEY` | | Where `monitors.json` goes; unset, to `GLN_CONFIG_DIR` |
| `GLN_CONFIG_DIR` | `.local/config` | Local `monitors.json` |
| `GLN_PAGE_BUCKET`, `GLN_PAGE_REGION` | region `eu-west-1` | The primary page bucket; unset, files go to `GLN_PAGE_DIR` |
| `GLN_PAGE_DIR` | `.local/pages` | Local page files |
| `GLN_PAGE_URL` | `http://localhost:4321` | The page's address, for links in feeds and email |
| `GLN_APP_KEY` | a fixed local key | Required with the Data API; the same value as the API's |
| `GLN_EMAIL_FROM` | | Sends through SES as this address; unset, to `GLN_MAIL_DIR` |
| `GLN_SES_CONFIGURATION_SET` | `galena-dev` | The SES configuration set |
| `GLN_MAIL_DIR` | `.local/mail` | Local email |
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` | | The worker access user's key |
