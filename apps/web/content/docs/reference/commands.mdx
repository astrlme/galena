---
title: Commands
description: Every script in the repository's root package.json.
---

Run these from the repository root.

| Command | What it does |
| --- | --- |
| `pnpm dev` | Starts Postgres and DynamoDB Local in Docker, applies migrations, seeds a workspace, then runs the dashboard, status page, API and a simulated hot path |
| `pnpm trigger:dev` | Runs the workers against your trigger.dev project's development environment |
| `pnpm check` | Lint, typecheck, unit tests and dependency rules; run before every commit |
| `pnpm lint` | Biome |
| `pnpm format` | Biome, fixing what it can |
| `pnpm typecheck` | TypeScript across the workspace |
| `pnpm test` | Unit tests (Vitest) |
| `pnpm test:int` | Integration tests against Postgres and DynamoDB Local in Testcontainers |
| `pnpm test:e2e` | Playwright with axe against local dev, light and dark |
| `pnpm check:page` | The status page's JavaScript and HTML budgets, Lighthouse and axe |
| `pnpm replay` | The detection rules against recorded check results in `test/fixtures/replay/` |
| `pnpm check:deps` | dependency-cruiser's import rules |
| `pnpm db:generate` | Generates a migration after a schema change |
| `pnpm db:migrate` | Applies migrations to the local database |
| `pnpm db:seed` | Seeds the local database; refuses any other |
| `pnpm api:generate` | Writes `apps/api/openapi.json` and the dashboard's typed client after route changes |
| `pnpm infra:synth` | CDK synth with cdk-nag |
| `pnpm infra:diff` | `cdk diff` against the `dev` stage |
| `pnpm deploy:dev`, `pnpm deploy:prod` | `cdk deploy --all` from your machine, with your own AWS credentials |

For one package: `pnpm --filter @galena/core test`.

<Callout type="warn">
`pnpm deploy` without a suffix is pnpm's own command, which copies a workspace package. It
doesn't deploy anything.
</Callout>

The normal way to deploy is the **Deploy** workflow in GitHub Actions; see
[Deploys and migrations](/docs/operations/deploys/).
