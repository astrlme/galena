title: CLI
description: galena init writes a deployment's config, galena deploy deploys or upgrades it, galena doctor checks it, and galena slack-manifest describes its Slack app.
---

Run the CLI with `npx @astrlme/galena <command>`, or `npx @astrlme/galena@<version> <command>`
for a given release. `init` writes `galena.config.json` in the current directory and the other
commands read it from there; pass `--config <path>` for another file. Each version installs its
source and dependencies once in `~/.galena/<version>` on its first run. From a clone of the
repository, run `pnpm galena <command>` at its root instead.

## galena init

Asks a few questions and writes the config. Answers can also be piped in, one per line.

| Question | Becomes |
| --- | --- |
| Deployment name | `stage` |
| Regions: eu or us | `homeRegion`, `probeRegions` and `pageRegions`, from the preset below |
| Status page domain | `pageDomain`, or nothing to use its CloudFront address |
| Dashboard domain | `webDomain`, or nothing to use its CloudFront address |
| Domain email is sent from, and the sender | `email`, or nothing to send no email |

| Preset | Home | Probes | Page, then its replica |
| --- | --- | --- | --- |
| `eu` | eu-central-1 | eu-west-1, eu-west-3, eu-north-1 | eu-west-1, eu-north-1 |
| `us` | us-east-2 | us-east-1, us-west-1, us-west-2 | us-west-2, us-east-1 |

It sets 5 read and 5 write telemetry units and an Aurora ceiling of 2 ACU, and leaves GitHub
deploys and the smoke test off; edit the file for those (see
[Configuration](/docs/reference/configuration/)). An answer the config would refuse is asked
again. It never replaces an existing file unless you pass `--force`.

## galena deploy

Deploys the config's deployment with your AWS credentials, or upgrades it: run it again with a
newer release. Each step checks first and skips what is already done.

1. Checks Node and your AWS credentials, and compares what your deployment records with the
   code it runs: its release (`/galena/<stage>/version`) and the last migration its database ran
   (`/galena/<stage>/schema`). An older release, or code without that migration, is
   refused, since the database only moves forward; `--force` deploys it anyway.
2. Bootstraps CDK in every region that needs it.
3. Stores secrets as SecureStrings under `/galena/<stage>/`: a new auth secret and app key, and a
   one-time setup token on the first deploy.
4. Builds the dashboard and deploys every stack, the background jobs included, several at a time
   where they don't depend on each other. With custom domains, it prints each certificate's
   validation CNAME while CloudFormation waits for it, and again every two minutes until ACM
   sees it; add them at your DNS host.
5. On the first deploy, asks for the workspace name and the owner's name, email and password,
   creates them through first-run setup, and deletes the setup token.
6. Prints the dashboard and status page addresses and the DNS records still needed, then runs
   `galena doctor`.

It prints no secret, and keeps the ones it makes only in SSM.

## galena doctor

Checks a deployment against its config with your AWS credentials, and changes nothing. It reads
the names of your secrets, never their values, and asks GitHub for the latest release.

| Check | What it reads | Not ok when |
| --- | --- | --- |
| `node` | The Node version running it | Older than 24 |
| `aws` | Who your credentials belong to | There are none |
| `bootstrap` | CDK's bootstrap version in every region the deployment uses, us-east-1 included | A region isn't bootstrapped |
| `parameters` | The SecureStrings under `/galena/<stage>/` | `auth-secret` or `app-key` is missing or not a SecureString |
| `heartbeat` | The [outside heartbeat](/docs/operations/troubleshooting/#outside-heartbeats) URLs under `/galena/<stage>/` | `evaluator-heartbeat` or `jobs-heartbeat` is missing or not a SecureString: a warning |
| `stacks` | Every stack the config creates, in its region | One is missing or failed. One still updating, or whose last update rolled back, is a warning |
| `version` | The version the deployment runs, the CLI's, and the latest release on GitHub | A warning when they differ or none is recorded. GitHub not answering within 5 seconds leaves the latest release out |
| `dns` | The CNAME of each custom domain | It doesn't point at its CloudFront distribution (with Cloudflare, also when the record is proxied) |
| `email` | Your SES identity and account | The domain, DKIM or MAIL FROM isn't verified. SES still in the sandbox is a warning |
| `telemetry` | Provisioned DynamoDB capacity of every table in the home region, any app's | Past the free tier's 25 read or write units (one free tier for a whole AWS Organization): a warning |
| `lambda` | Concurrent Lambda executions allowed in the home region | Fewer than 100: a warning |

Each check prints one line, `ok`, `warn` or `fail`, with what to fix under it. `--json` prints
the checks as an array of `{ id, status, summary, details }` instead. The exit code is 1 when a
check fails; warnings leave it at 0.

## galena slack-manifest

Prints the manifest for the deployment's own Slack app, as JSON, with every request URL pointing
at its dashboard: `webDomain` when the config has one, otherwise the dashboard's CloudFront
address (so deploy first). Paste it into Slack's **Create an app → From a manifest**. See
[Approvals in Slack](/docs/guides/slack-app/).
